HARDWARE (T-Deck Pro)
---------------------
Panel     : GDEQ031T10, 320×240, controller UC8253
EPD pins  : CS=34  DC=35  BUSY=37  RST=16
SPI       : SCK=36  MOSI=33  MISO=47  (shared with LoRa)
Power     : BOARD_1V8_EN, BOARD_LORA_EN must be HIGH before display/SPI
LoRa      : SX1262, keep LORA_CS high when talking to e-ink
BoardConfig: src/boards/tdeck_Pro/config/BoardConfig.h  (source of truth)

WHAT FAILED EARLIER (do not repeat)
-----------------------------------
  - Hand-rolled DisplayEink used SSD1680-style commands (0x24 / 0x22 / 0x20).
    UC8253 needs: write 0x10 (old) + 0x13 (new), refresh 0x12, BUSY active LOW.
  - -mfix_size=16MB as a build_flag (invalid; flash size is board_build.*).
  - Pulling full Plus LvglApplication into standalone before panel worked.
  - handheld_lvgl_fail signature is void (no message arg); match LvFailure.h.

CURRENT RECOMMENDED ARCHITECTURE
--------------------------------
  Prefer GxEPD2 for the panel driver in standalone (proven on hardware).
  Thin LvglPort: LVGL 1-bit flush → buffer → GxEPD2 writeImage + refresh.
  Custom bare DisplayEink is optional later; if written, mirror GxEPD2’s
  UC8253 sequence exactly.

STANDALONE BUILD RULES
----------------------
[env:tdeck_pro_standalone]
  extends tdeck_Pro_base
  build_src_filter:
    +<core/>
    -<core/runtime/LvglApplication.cpp>
    -<ui/lvgl/>
    +<boards/tdeck_Pro/>
  Do NOT add -mfix_size=* to build_flags.
  BOARD_HAS_PSRAM ok; flash size comes from lvgl16_base board_build.*.

LVGL custom hooks (when enabling LVGL again)
  LvMemory.h : handheld_lvgl_alloc / free / realloc / memory_stats
  LvFailure.h: handheld_lvgl_fail(void)  — no const char* argument
  Font stand-in: lv_font_rsdeck_14 → montserrat_16 until real rsDeck fonts linked
