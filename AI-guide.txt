HARDWARE (T-Deck Pro)
---------------------
Panel     : GDEQ031T10, 240×320, controller UC8253
EPD pins  : CS=34  DC=35  BUSY=37  RST=16
SPI       : SCK=36  MOSI=33  MISO=47  (shared with LoRa)
Power     : BOARD_1V8_EN, BOARD_LORA_EN HIGH before display/SPI
LoRa      : keep LORA_CS high when talking to e-ink
I2C       : SDA=13 SCL=14 (BQ27220 battery, keyboard, touch)
BoardConfig: src/boards/tdeck_Pro/config/BoardConfig.h  (source of truth)

BITMAP / COLOR CONVENTION (do not invert again)
-----------------------------------------------
  FB bit 1 = black on panel, bit 0 = white.
  setPixel(black): |= mask;  setPixel(white): &= ~mask
  Initial FB: memset 0x00 (white).
  fullRefresh: fillScreen(WHITE) then drawBitmap(..., GxEPD_BLACK).
  LVGL: c.full == 0 → black pixel. Do not use c.ch.green (LV_COLOR_16_SWAP).

UI TEXT RULES
-------------
  - Use only characters present in lv_font_montserrat_16.
  - Prefer ASCII: "-", "--", "n/a", "0". Never use em-dash (U+2014) or other
    fancy punctuation that triggers "glyph dsc. not found".

KNOWN POLISH (non-blocking)
---------------------------
  - Right-column values can clip near the edge; tighten padding/columns later.
  - Footer / long strings can overlap; shorten or use two lines.
  - FB often via malloc (PSRAM fallback); OK for bring-up.
  - Partial refresh not implemented yet (always full when dirty).
  - Full ProtocolRuntime + radio + MessageStore not yet in standalone main.

WHAT FAILED EARLIER (do not repeat)
-----------------------------------
  - Bare UC8253 with SSD1680 cmds (0x24/0x22/0x20). Use GxEPD2.
  - -mfix_size=16MB as build_flag.
  - LvglApplication in standalone before panel worked.
  - handheld_lvgl_fail(const char*) — real API is fail(void).
  - FB bit 0 = black (inverted vs GxEPD2 drawBitmap).
  - Em-dash "—" in UI strings → LVGL glyph warnings (U+2014).
